# Project Workflow

All-group meeting happen every Sunday, 4-5pm over zoom. These meetings are meant to: 
- Review updates and features implemented in the previous week
- Set new goals for the upcoming week
- Break the goals into issues and assign responsibilities
- A new member will take notes each week. Meeting minutes can be found in `\meeting-notes`

All-group Sprint Meetings happen every Tuesday and Thursday 6:20 - 6:45pm in Catalyst. These meetings are meant to: 
- Quickly review progress of tasks
- Address blockers for any devs
- Opportunity to ask questions, make comments, and ask for help
- Reminder of upcoming goals and expectations
- Aila will take notes each sprint meeting. Meeting minutes can be found in `\meeting-notes\sprint-meetings.md`

  
When adding or changing something in the project, team members should follow this basic workflow:

1. Create or claim a GitHub issue.
2. Create a branch for the task.
3. Manually create unit tests for the feature to guide the development. 
4. Implement the change.
5. Commit with a clear message.
6. Open a pull request.
7. Link the pull request to the related issue.
8. Update the team on the PR being made, and wait unil someone reviews the PR
9. Make the necessary updates or discuss the comments of the reviewer if applicaple
10. Merge the PR into the version of that week. 

Example branch names:
```txt
docs/update-readme
docs/add-generation-log
feature/text-on-image
feature/image-download
test/download-feature
fix/mobile-layout
```
